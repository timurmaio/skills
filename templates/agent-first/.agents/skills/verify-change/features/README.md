# Карта фич для browser verification

Как дойти до пользовательской фичи, чем её проверить и что считается доказательством. Читай перед проходом в браузере, бери файл фичи как рецепт. Запуск, вход, Doctor и cleanup — в [browser-testing.md](../../../../docs/engineering/browser-testing.md).

## Базовое состояние

- `pnpm dev` этого worktree на `localhost:{{DEV_PORT}}`, `pnpm browser:login` прошёл, `pnpm browser:doctor` — все `OK`.
- Dev-пользователь из `.env.browser.local`, данные dev-контура. После входа открыта стартовая страница приложения.
- Каждый рецепт начинается с прямого перехода по URL: `pnpm browser -- open http://localhost:{{DEV_PORT}}/<route>`.

## Как водить

- Переходи по URL, а не по меню: пункты меню часто без доступного имени.
- Элементы ищи по роли и имени: `pnpm browser -- find role button click --name "Apply" --exact`, `find label "<label>" fill "<value>"`. Refs из snapshot — только до следующего изменения страницы.
- Сеть для evidence — только method, host+path и status (`pnpm browser:network`).

## Что считается доказательством

- Действие и результат: что нажали и что изменилось — строки таблицы, значения, URL, запрос со статусом.
- Нули и пустые таблицы у dev-пользователя — нормальные данные. Ошибку доказывает статус запроса или `errors`, а не пустой экран.
- Mutation: запрос со статусом плюс сохранённое состояние после reload.
- Не хватает предусловия — сценарий `blocked` с причиной, а причина — в «Подводные камни» фичи.

## Фичи

Один файл на пользовательскую фичу по образцу [_template.md](_template.md). Файл появляется, когда агент первый раз проходит фичу в браузере; `maintain-verification-skill` держит карту в соответствии с кодом.

Пока фич нет.
