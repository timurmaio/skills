# Очередь повторов агентов

Сюда раз в неделю каждый разработчик дописывает, на чём агенты спотыкались в его сессиях. Правки по очереди делаются отдельно: так видно общие причины, которые по одной сессии не заметишь. Порядок — в [setup.md](setup.md#разбор-сессий-как-устроен).

## Как дописывать

Новая запись — сверху, под «Записи»:

```markdown
### YYYY-MM-DD — Имя, окно YYYY-MM-DD…YYYY-MM-DD

| Класс          | Случаев | Пример                                  | Уровень | Правка        |
| -------------- | ------- | --------------------------------------- | ------- | ------------- |
| <одна причина> | 3       | <короткая цитата поправки без секретов> | lint    | <что сделать> |

Задачи: 10, без вмешательств 7, дефектов после READY 2.

Потери времени: <долгий поиск, тяжёлые вызовы, нехватка доступа | —>
```

Уровень — самый высокий из работающих: архитектура, типы, lint, тест, правило. Без секретов, данных клиентов и длинных цитат.

Строка «Задачи» показывает не только провалы, но и долю задач, которые агент довёл сам: по ней решают, где расширять автономию.

- **Задачи** — задачи с правкой кода в окне, которые агент довёл до `READY` от `verify-change`.
- **Без вмешательств** — из них те, где пользователь не поправлял ход работы между запросом и `READY`. Ответ на вопрос агента о продукте или scope и разрешение на внешнее действие вмешательством не считаются.
- **Дефектов после READY** — ошибки в этих задачах, найденные позже: ревью, QA, CI или fix-коммит.

После разбора класс, который закрыли, помечается ссылкой на коммит: `закрыто — abc1234`.
