# Guardrails агентов

Как правила из [AGENTS.md](../../AGENTS.md) держатся проверками в каждом инструменте. Выбор skill — в [flow.md](flow.md), устройство сетапа — в [setup.md](setup.md).

## По инструментам

Правило в тексте агент может пропустить, поэтому guardrails из [AGENTS.md](../../AGENTS.md) по возможности держит проверка. У каждого инструмента свой механизм; где его нет, остаётся только текст.

| Правило                        | Claude Code                                                         | Cursor                                                               | Codex                                                               |
| ------------------------------ | ------------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Значения env не читать         | `.claude/settings.json`: запрет `Read` — и для `cat`, `head`, `sed` | `.cursorignore`: закрыты файловые инструменты агента, терминал — нет | только текст: запрет чтения есть лишь в beta-профилях разрешений    |
| `git push` — только по запросу | `.claude/settings.json`: `git push` спрашивает подтверждение        | только текст: проектной настройки нет                                | `.codex/rules/project.rules`: спрашивает; грузится в trusted-проекте |
| Не пушить в защищённые ветки и не переписывать историю | хук `scripts/hooks/guardGitPush.mts`: отказ без вопроса | только текст | только текст; надёжная граница — protected branches на хостинге |
| «Готово» только после verify   | Stop-хук `scripts/hooks/stopWithoutVerify.mts`: не даёт закончить сессию с правками кода без свежего `pnpm verify` | только текст | только текст |
| Vendored skills не патчить     | `pnpm lint:skills` в `pnpm check`, падает и в CI                    | тот же `pnpm lint:skills`                                            | тот же `pnpm lint:skills`                                           |

Новый запрет добавляй во все механизмы, где они есть; `pnpm check` надёжнее всего — он входит в `pnpm verify` и падает в CI.

## Хуки Claude Code

Хуки подключены в `.claude/settings.json` и лежат в `scripts/hooks/`. Сбой хука работу не блокирует: правило остаётся в тексте.

- **SessionStart** запоминает дерево файлов в начале сессии, **Stop** сравнивает с ним текущее. Изменён код (не только Markdown), а последний успешный `pnpm verify` был на другом дереве — Stop один раз возвращает агента к `verify-change`. Остановку с вопросом или с `NOT READY` хук пропускает со второго раза. Отметки лежат в git-каталоге checkout, у каждого worktree свои.
- **PreToolUse** для Bash отказывает в `git push` в ветки из `PROTECTED_BRANCHES`, `--force` без lease, `+refspec`, `--all` и `--mirror`. Прочий push спрашивает подтверждение через `permissions.ask`; для автономного режима его можно разрешить, отказ хука при этом остаётся.
