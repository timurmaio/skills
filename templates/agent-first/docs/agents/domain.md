# Domain docs

Как engineering skills читают доменную документацию репозитория. Формат по `setup-matt-pocock-skills` (mattpocock/skills), раскладка multi-context.

## Перед исследованием прочитай

- **`GLOSSARY-MAP.md`** в корне: он ведёт к `GLOSSARY.md` каждого домена (`src/features/<domain>/docs/GLOSSARY.md`). Прочитай словари доменов, которых касается задача.
- **ADR**: общесистемные — `docs/adr/`, доменные — `src/features/<domain>/docs/adr/`. Читай те, что касаются места правки.
- **Документацию домена** в `src/features/<domain>/docs/`: спецификации, runbook, жизненный цикл сущностей. Документ, который меняет реализацию, зарегистрирован условием в [CODING_STANDARDS.md](../../CODING_STANDARDS.md).

Каких-то файлов нет — продолжай молча: не отмечай их отсутствие и не предлагай создать заранее. Словари и ADR создаёт `domain-modeling`, когда термин или решение действительно приняты; новый словарь регистрируй в `GLOSSARY-MAP.md`.

## Структура

```text
/
├── GLOSSARY-MAP.md
├── docs/adr/                         ← общесистемные решения
└── src/features/
    ├── <domain-a>/docs/
    │   ├── GLOSSARY.md
    │   └── adr/                      ← решения домена
    └── <domain-b>/docs/
        └── GLOSSARY.md
```

## Пиши терминами словаря

Доменное понятие в заголовке ticket, предложении рефакторинга, гипотезе или названии теста называй так, как в `GLOSSARY.md`. Синонимы, которых словарь избегает, не используй.

Нужного понятия в словаре нет — это сигнал: либо ты придумываешь язык, которым проект не говорит, либо в словаре настоящий пробел — отметь его для `domain-modeling`.

## Противоречие ADR — скажи явно

Если твой результат противоречит ADR, не обходи его молча:

> _Противоречит ADR-0007 (…), но стоит пересмотреть, потому что…_

## Источники истины

- Термины — локальные `GLOSSARY.md`, определения хранятся в репозитории, без внешних указателей вместо словаря.
- Фактическое поведение — код. Внешние вики (Notion, Confluence) — справочный материал: они могут расходиться с реализацией.
- Устойчивые технические знания — в ближайшем `src/features/<domain>/docs/`, а не только внутри завершённого плана.
