# Стилизация

[Карта инженерной документации](../../CODING_STANDARDS.md). Часть [styleguide](styleguide.md); пометки «Lint:» — как там.

## Стилизация

- **Tailwind CSS:** Максимально используйте утилитарные классы Tailwind CSS для стилизации. Это основной подход.
- **Семантические токены цветов:** Для цветов в `className` — только semantic-токены дизайн-системы (например, `text-fg-*`, `bg-surface-*`, `border-stroke-*`). **Запрещено:** palette-классы (`text-zinc-*`, `bg-gray-*`), кастомные одноразовые `@theme`-цвета, hex/rgb в arbitrary values, если есть подходящий токен. Смысл цвета — из роли токена, не из оттенка palette.
- **Семантические токены типографики:** Для размера текста в `className` — только типографические токены дизайн-системы (например, `text-heading-*`, `text-body-*`, `text-caption`). **Запрещено:** `text-sm`, `text-xl`, `text-[Npx]` и другая шкала Tailwind. Storybook stories проверяются наравне с production UI.
- **Design-system компоненты и `className`:** У компонентов дизайн-системы `className` допустим только для внешнего layout-контекста: ширина, внешний отступ, позиционирование во flex/grid, `grow`/`shrink`, `self-*` и подобные контейнерные настройки. Через `className` нельзя переопределять их внешний вид: цвета, фон, border, radius, shadow, typography, внутренние отступы, hover/pressed/active-состояния.
- **Внутренний layout UI-компонента принадлежит компоненту:** В consumer-коде запрещено задавать через `className` самого UI-компонента классы, управляющие расположением его внутренних элементов: `flex-row`/`flex-col`, `grid-cols-*`, `gap-*`, `space-*`, `items-*`, `justify-*`, `flex-wrap` и аналогичные. Типизированный prop/variant (`layout`, `orientation`, `density`) добавляйте только при появлении реального повторяющегося consumer-сценария, а не заранее; до этого не обходите контракт через произвольный CSS.
- **Не добавляйте `*ClassName` для внутренних частей UI-компонента:** Не расширяйте API дизайн-системы пропсами вроде `listClassName`, `contentClassName`, `triggerClassName`, `iconClassName`, если они дают потребителю менять layout или внешний вид внутренних DOM-узлов. Обычно допустим максимум один корневой `className` для позиционирования компонента в родительском layout. Размеры, плотность, ориентацию и другие устойчивые варианты оформляйте через явные props/variants.
- **Внешний вид компонентов через API:** Размер, вариант, тон и другие визуальные состояния задавайте через `size`, `variant` и другие явные props/variants компонента. Если нужного варианта нет, сначала расширяйте API компонента, а не обходите его через `className`.
- **Slots не обходят дизайн-систему:** Не подменяйте стандартные внутренние элементы UI-компонента собственной разметкой через `children`/slots ради другого размера, отступов или внешнего вида. Например, для обычной иконки кнопки используйте `leftIcon`/`rightIcon`, а не slot с вручную стилизованной иконкой. Slots — для содержимого, отличающегося по смыслу от стандартного элемента, например аватара или badge.
- **Ширина модальных окон только через `size`:** Для диалогов запрещено переопределять ширину через `className` или arbitrary-классы вроде `max-w-[560px]`. Используйте ближайший существующий вариант `size`; новый вариант добавляйте только для повторяющегося продуктового размера, а не для единичного макета.
- **Инлайн-стили:** Статическое оформление задавайте через Tailwind или CSS Modules. Атрибут `style` допустим для runtime-значений, которые нельзя выразить конечным набором классов: вычисляемых размеров и координат, CSS custom properties, параметров анимации, style-контрактов библиотек (размеры колонок, виртуализация). Инлайн-стили не должны обходить semantic-токены, variants или другой публичный API дизайн-системы.
- **CSS Modules:** Используйте файлы `.module.css` в тех редких случаях, когда Tailwind не подходит. Например, для сложных анимаций или стилей, зависящих от множества динамических состояний.
- **tailwind-variants:** Для компонентов с несколькими визуальными состояниями используйте `tailwind-variants`, а не сборку длинных условных строк в JSX. Boolean variants называйте в стиле render-state: `isSelected`, `isDisabled`, `isHovered`, `isFocused`, `isPressed`. Файл со стилями называйте рядом с компонентом, например `Component.styles.ts`.
- **Семантические HTML-теги для текста:** Для текстовых блоков используйте семантические теги `p` (параграф) или `span` (инлайн-текст), а не `div`. Это улучшает доступность и семантику разметки.

  ```tsx
  // ПЛОХО: palette и шкала Tailwind вместо токенов
  <p className="text-sm text-zinc-500">Описание функции</p>

  // ХОРОШО: p + semantic-токены
  <p className="text-body-medium text-fg-subtle">Описание функции</p>

  // ХОРОШО: span для инлайн-текста
  <span className="text-body-medium text-fg-subtle">Дополнительная информация</span>
  ```
