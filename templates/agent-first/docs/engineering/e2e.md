# Локаторы для E2E

[Карта инженерной документации](../../CODING_STANDARDS.md).

E2E-тесты (Playwright или аналог) ищут элементы интерфейса. Этот документ — договорённость, по которой мы размечаем UI, чтобы тесты не ломались от правки разметки, стилей и текстов.

Пример: поле «Название» находится как `page.getByTestId("orders-form-title").getByRole("textbox")`, очистка поля «Страны» — `page.getByTestId("orders-form-countries--clear")`, его открытый список — `page.getByTestId("orders-form-countries--popover").getByRole("listbox")`. Имена id в примерах условные.

## Контракт

Контракт для E2E — `data-testid` как точка входа и роль без имени внутри неё.

- **Входит:** `data-testid` и роль элемента.
- **Не входит:** строки интерфейса из переводов, XPath, CSS-классы, структура DOM, место portal, HTML `id`, `data-key` и `slot`. Всё это меняется без предупреждения авторов тестов.
- **Данные теста допустимы.** Имена сущностей, которые тест сам создал или взял из фикстуры, используются в `filter({ hasText })` и `getByRole("option", { name })`. Поэтому опциям каталога свой test id не нужен.
- **Accessible name** обязателен для доступности: test id его не заменяет, пользователь скринридера слышит переведённое имя. E2E на имя не опираются.

## Кто получает test id

- root поля формы;
- root составного виджета: селект, мультиселект, календарь, таблица, диалог, вкладки;
- интерактивный элемент вне поля, нужный в сценарии: кнопка действия, ссылка-действие, переключатель;
- строка коллекции.

Test id ставится на существующий root. Wrapper ради теста не добавляется.

## Достижимость

Интерактивный элемент достижим, если у него свой test id или если ближайший предок с test id содержит ровно один элемент этой роли. Так его находит `getByTestId(scope).getByRole(role)` без имени и без позиции.

Интерактивные роли: `button`, `link`, `textbox`, `searchbox`, `combobox`, `checkbox`, `radio`, `switch`, `spinbutton`, `slider`, `tab`, `menuitem`, `menuitemcheckbox`, `menuitemradio`. Опции каталога, элементы дерева и строки коллекций (`option`, `treeitem`, `row`, `gridcell`) в список не входят: их находят по [данным теста](#контракт), а строку — по id сущности.

Ровно один — считая вложенные scope: если в root селекта есть trigger и кнопка очистки, обе роли `button`, и каждой нужен свой производный id.

## Нейминг

- **Общий вид:** `<domain>-<surface>-<control>[-<action>]` в kebab-case, по бизнес-смыслу: `orders-bulk-delete-dialog`.
- **Без** случайных hex и UUID, индекса, позиции, CSS, текста интерфейса и PII. Id описывает, что это, а не как оно выглядит или где стоит.
- **Форма:** `<domain>-form-<control>`, например `orders-form-title`. Один id во всех режимах формы (create, edit, разные версии API и раскладки). Две формы на экране различаются через scope диалога.
- **Коллекции:** стабильный доменный id сущности: `` `order-row-${order.id}` ``. Не индекс строки. Нет id у сущности — номер, который пользователь видит рядом с ней. Номера на экране нет — номер добавления, который не переиспользуется после удаления.
- **Списки:** `<domain>-list-<control>`, фильтры — `<domain>-list-filters-<control>`, root таблицы — `<domain>-list`.
- **Состояния страниц:** «не найдено» — `<domain>-form-not-found`, ошибка загрузки — `<domain>-form-error`. Общий для приложения блок получает id без домена: `layout-access-denied`.

## Части виджета

Часть составного виджета получает id `<root>--<part>`: двойной дефис отделяет часть от root.

| Часть                       | Id                                                          |
| --------------------------- | ----------------------------------------------------------- |
| trigger селекта             | `orders-form-countries--trigger`                            |
| открытый popover (в portal) | `orders-form-countries--popover`                            |
| очистка значения            | `orders-form-countries--clear`                              |
| выбранный тег               | `` `orders-form-countries--tag-${id}` ``                    |
| сегмент даты и времени      | `orders-form-start-date--day`, `--month`, `--hour`          |
| вариант радио и сегмента    | `` `orders-form-placement--option-${value}` ``              |
| пункт меню                  | `` `order-row-actions--item-${id}` ``                       |
| кнопки диалога              | `orders-bulk-delete-dialog--submit`, `--cancel`, `--close`  |
| ошибка в диалоге            | `orders-bulk-delete-dialog--error`                          |
| строка таблицы              | `` `orders-list--row-${id}` ``                              |
| колонка и фильтр таблицы    | `` `orders-list--column-${columnId}` ``, `` `--filter-${columnId}` `` |
| пагинация таблицы           | `orders-list--pagination--prev-page`, `--next-page`         |

- Компонент дизайн-системы получает один `data-testid` на root и сам выводит id частей. Без root id производных id нет.
- Root — внешний элемент компонента: label, hint и действия рядом с label лежат внутри него.
- Unit-тест части ищет её так же, как E2E: по производному id или ролью без имени внутри scope. Поиск по accessible name скрывает недостижимый элемент.
- Popover рендерится в portal вне root, поэтому ищется по своему производному id, а не внутри root.
- Dialog несёт test id на элементе с ролью `dialog`, а не на подложке.
- Часть по значению берёт стабильный ключ, а не текст: `value` варианта, тип сегмента даты, ключ колонки, id пункта. Ключ — в kebab-case: колонка `created_dt` — `--column-created-dt`.
- Самописный виджет приложения выводит части так же: принимает test id root и строит id частей одним helper.

## Состояние

Test id не меняется со сменой состояния: `orders-form-submit`, а не `orders-form-submit-disabled`. Состояние читается из `disabled`, `aria-disabled`, `aria-selected`, `aria-expanded`, `aria-invalid` и `data-pending`.

## Production

Если E2E гоняют на production-сборке, test id остаются в сборке: не включайте удаление `data-testid` в настройках компилятора.

## Contract test

Пропуски разметки ловит contract test экрана: он рендерит экран, обходит интерактивные элементы и падает на недостижимом (правило [достижимости](#достижимость)). Новый экран или фича с UI размечается по этому документу и подключает contract test в том же изменении.
